# Windows ops: wersje i granice

Kanoniczny aktywny kontroler: `deployment/r2/controller/`, instalacja `core-e8160a07-full-local-r1-v2`, zachowuje poprawki FIX5: natywne wyniki procesu przedDispose, potem świeże SCM/CIM bez własnych uchwytów, kontrakt wyników STOP, utrzymanie bariery po błędzie, przywracanie dokładnegoEnabled i porównanie XML bez jednego elementuEnabled. Kolejność STOP mangosd→realmd→MySQL, START odwrotnie. Nonzero/timeout/UNKNOWN blokują następną zależność. Kod źródłowy oraz jego zależności są dostarczone, nie tylko ścieżki.

`deployment/r2/` to odebrany pakiet produkcyjny z generatorami preimages CREATE DATABASE→USE w tym samym mysql.exe, pełnym PK(entry,patch)/(guid,quest), odbiorem wszystkich kolumn i brakiem automatycznego replay/restore. Oryginalny Verify-Deployment ma historyczny błąd oczekiwania i nie jest obecnym odbiorem; właściwa korekta jest w `verification/r3/`. R3 jest ścisłym verifierem konkretnej operacji, a nie zgodą dla dowolnego późniejszego release.

`dev/full-candidate/` zawiera kontynuację realnego DEV i porównania pełnychPK; `dev/fix5/` jest przypiętą bazą modułów/tras i lifecycle dla odrębnegoDEV. To jedna aktualnie wymagana baza zależności, nie kopie wszystkich historycznychFIX1–FIX4. `collector/` odpowiada zainstalowanemu COLLECTOR-RELEASE-MANIFESTS-R4-R2/20261025-2348. Polityka zawiera wyłącznie WOW-SRV ścieżki i publiczne piny, nie DPAPIsecret. Dane rejestru, activeapproval/capability receipts, runtimepointer/state, claims/journals i snapshoty nie są dołączone.

`common/process-capture/` zawiera rzeczywisty zatwierdzony reader nativeexit/stdout/stderr. `host-contracts/WOW-SRV/bridge/` zawiera aktualne skrypty routingu; plik bieżącego bundle nie jest eksportowany. `profiles/` obejmuje profil1×12 oraz odczytowe narzędzia pomiarów, bez logów produkcyjnych.

Większość skryptów jest świadomie host-specific i zachowuje absolutne piny/guardy. Handoff nie jest nową operacyjną paczką instalacyjną. Oryginalne EXECUTION-PINS/KIT-PLAN dokumentują pochodzenie i wiązania; po bezpiecznych zmianach publicznych szablonów autorytatywne bajty tej dostawy są w MANIFEST-SHA256.tsv. Nie uruchamiać tych skryptów z kopii ani nie przepisywać pinów dla przejścia kontroli. Portowanie wymaga rebindingu, regeneracji pinu/seala i osobnego review/testów.

Przenośne idee: uporządkowany sequencer, ograniczony wait, wierne UNKNOWN, native capture, porównanie zbiorów i jednoznaczne receipty. WOW-SRV kontrakty: nazwyusług/porty, SYSTEM/AppPool/SDDL, registryRoot, katalogi, DPAPI, taskXML, approvalScope i konkretne releasehashes. Nie wysyłamy aktywnych zgód. Planowany reboot oraz bootowyStartAll mają odrębne intencje; ManualStop/Maintenance pozostają zatrzymane. Bezpośredni Windowsshutdown/PRESHUTDOWN/SCMrecovery nadal nie jest dowiedziony przez deployment.
