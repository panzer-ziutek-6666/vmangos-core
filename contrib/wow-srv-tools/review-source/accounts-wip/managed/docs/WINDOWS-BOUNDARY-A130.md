# A130 — kontrakt przyszłej granicy wykonania na Windows

Ten dokument określa niewykonany zakres. A130 nie instaluje żadnego z poniższych elementów.

1. Wersjonowany fixed worker SYSTEM, chroniony kod/journal/credentials dostępny wyłącznie SYSTEM i Administrators. IIS/AppPool nie odczytuje ani nie modyfikuje sekretu i journal. Prawdziwe soap.bin collectora pozostaje nietknięte; brak rozszerzenia jego ACL/allowlisty.
2. Lokalny named pipe: remote clients odmówieni, pierwszy instance wymagany, ACL tylko SYSTEM i dokładny AppPool SID `S-1-5-82-2192834305-681035450-1731772730-1791053079-2169464979`. Wzajemna weryfikacja rzeczywistego tokenu/SID, executable SHA/path, PID+CreatedUtc, generacji i handshake. Zaufane PeerProof nie pochodzi z ramki. Limity czasu handshake/read/write, ramka do 4096 B, jedna ustalona operacja, bez hasła w task arguments/env/disk queue.
3. Wspólny `Global\VMANGOS-AdminPanel-Control` oraz trwały pending/unknown gate. Każda ścieżka sterowania w zakresie musi sprawdzać journal/pending wewnątrz wspólnej blokady; abandoned mutex nie usuwa niepewności. Sprawdzić także boot task i bezpośredni VMANGOS-Control.ps1, który obecnie nie ma takiej blokady. Nie aktualizować samego bridge, pozostawiając możliwość ominięcia guardu przez inną ścieżkę. Zmiany będą oddzielnym jawnie przypiętym payloadem z backupem.
4. Nowy journal inicjalizowany jawnie, atomowo CreateNew, z receipt i stałą ścieżką. Brak/uszkodzenie pliku, brak dostępu, capacity/flush failure lub nierozstrzygnięta generacja oznaczają odmowę. Nie tworzyć automatycznie pustego journal po jego utracie. Snapshot terminalny nie jest kryptograficznie niezmienny; system plików/tokeny i polityka archiwizacji wymagają osobnych testów.
5. SOAP wyłącznie stały loopback 127.0.0.1:7878, bez proxy/redirect/retry. Uwierzytelnienie SEC_ADMINISTRATOR=6 i CLI dispatch SEC_CONSOLE=7 to osobne sprawdzenia; nie nadawać GM7 kontu SOAP. Potwierdzić prawdziwą tożsamość/security oraz kontrakt odpowiedzi, bez wypisywania credentials lub raw SOAP/fault.
6. Verifier tylko fixed SELECT: baseline braku nazwy, nowy account ID, GM0/account_access na wszystkich RealmID, defaulty, realmcharacters i szersza delta REPLACE, dowód zakończenia asynchronicznego zapisu. Bez SRP v/s/hashów/sessionkey i bez SQL DML/DDL. Flagi atrap w A130 nie zastępują tych odczytów i dowodów.
7. Testy rzeczywistych tokenów AppPool/SYSTEM: odmowy secret/code/journal/release/task/telemetry writes, spoof/precreation/remote pipe, zmiany generacji i crash, create vs Stop/Restart/boot, dowód jednego dispatch. Oddzielnie prawdziwy pipeline IIS HTTPS/operator/CSRF-before-body. Nie włączać funkcji na podstawie samych testów DefaultHttpContext.
8. Przed live: runner syntetycznej obserwacji i wymagane logi/sinki z planu A128, odpowiedni świeży backup i preflight. Brak danych = UNKNOWN. Każda instalacja i jeden pilot mają osobny zakres, manifest/backup/rollback i log. Wycofanie panelu nie cofa konta; brak automatycznego retry/delete/restore.
